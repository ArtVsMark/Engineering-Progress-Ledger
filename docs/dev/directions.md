# Карта направлений: кто обязан задать вопрос

> **Читатель:** владелец и окно — какие вопросы о продукте здесь задают, а
> какие не задаёт никто.

Заготовка механизмов (#1645). Направление — это **вопрос**, а не должность
([082](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/082-roles-must-cover-every-layer.md)):
список ниже — направления правила, исходы — ваши. По каждому поставьте один из
четырёх: **профиль** (вопрос задаётся, артефакт есть; чей — рядом), **роли нет**
(артефакт есть, вопрос не задаёт никто — дыра), **артефакта нет** (направление
названо, предмета ещё нет), **пласта нет** (предмета нет и не предвидится).

Пока стоит «не размечено», карта — намерение, а не замер. Ведёт карту навык
`direction-coverage`, владельцев направлений — `role-profile`; кто задаёт
вопросы — в [`roles.md`](../agent/roles.md).

## Делаем

| Направление | Исход | Чем держится или почему нет |
|---|---|---|
| Архитектор | профиль Архитектора | Граница слоёв: архив HTML `snapshots/` неизменен, данные и страница — производные (эпик #3); README «Устройство», `docs/agent/behaviour.md` |
| Разработчик прикладной | артефакта нет | Прикладного кода у журнала нет — свой только `bash` проверок и окружения; появится со сборкой базы и страницы (#5, #6) |
| Разработчик-предметник | роли нет | Свой код — `bash` джоба `snapshots` в `ci.yml` и слота хука старта; верно ли он читает семантику Actions (`GITHUB_BASE_REF`, ссылка слияния, `...` с базой), проверяет только откат на изменении, вопрос систематически не задаёт никто |
| Клиентская часть | артефакта нет | Страницы ещё нет (#6, #9) |
| Инженер платформы | профиль Потребителя механизмов | Прогоны `.github/workflows/*` — вызовы общих шагов поставщика по тегу; классы — `.pipeline.yml` |
| Инженер данных | артефакта нет | Базы снимков и объявления метрик ещё нет (#4, #5) |
| Релиз и цепочка поставок | артефакта нет | Выпусков у журнала нет, шаг `journal` выключен; нужны ли — решение #23 |
| ИИ в продукте | профиль Аналитика данных | Снимки — вывод внешней модели: числа внутри них сверяет аналитик данных, сравнимость между ними — Критик метода |
| Обучение моделей | пласта нет | Моделей журнал не обучает |

## Проверяем

| Направление | Исход | Чем держится или почему нет |
|---|---|---|
| Тестирование | профиль Тестировщика | Свой джоб `snapshots` в `ci.yml`, проверенный откатом в обе стороны |
| Аудитор | роли нет | Кто и когда менял журнал, сверяет гейт `attribution` по `.github/authors.txt`; вопрос «соответствует ли процесс журнала объявленному» сверх гейта не задаёт никто |
| Ревизор | профиль Ревизора | Декларации README и свода против дерева, классы `.pipeline.yml` против `ci.yml` |
| Верификатор | роли нет | Шаг `review / verify` поставщика проверяет премису находки по кнопке, но роли, которая её зовёт и судит исход, у журнала нет |
| Критик метода | профиль Критика метода | Сравнимость снимков: изменился мир или способ счёта; ответ — следующий снимок |
| Безопасность | профиль Потребителя механизмов | Права прогонов и закрепление действий по SHA — в вызовах `ci.yml`; гейт опасных форм прогонов — у поставщика |
| Данные и приватность | профиль Приватности | Журнал публичен, а снимок не правится: что кладётся, судит роль до слияния; страница без раздела о доходе — #9 |
| Производительность и ресурсы | пласта нет | Журнал — статические файлы; прогоны — короткие вызовы общих шагов |
| Совместимость | профиль Потребителя механизмов | Контракт механизмов в `.pipeline.yml`, тег в `uses:` прогонов; подъём — `onboard.py --update` |
| Правомерность | роли нет | Лицензии у журнала нет; копии механизмов несут строку MIT поставщика; права на содержимое снимков, полученных внешней моделью, не спрашивает никто |

## Понимаем и ведём

| Направление | Исход | Чем держится или почему нет |
|---|---|---|
| Системный аналитик | артефакта нет | Схемы снимка ещё нет (#5) |
| Аналитик продукта | профиль владельца | Кто и зачем читает журнал, знает владелец; данных о чтении нет |
| Аналитик данных | профиль Аналитика данных | Числа внутри снимка: итог против разбивки, повтор одного числа |
| Моделирование и прогноз | пласта нет | Журнал фиксирует, а не прогнозирует |
| Владелец продукта | профиль владельца | Эпик #3 и план работ — живая задача `work-plan` |
| Развитие | профиль владельца | Направление журнала решает владелец; задачи — в трекере |
| Внешние практики | профиль Потребителя механизмов | Практики семьи приходят механизмами поставщика и правилами каталога |
| Методология | профиль Критика метода | Как получен снимок и сравним ли он с прошлым |
| Специалист предметной области | роли нет | Оценку компетенций и рынка в снимках делает внешняя модель; проверяющего её по существу нет |
| Экономика работы | роли нет | Цену прогонов и окон журнала никто не считает |
| Исследователь | пласта нет | Исследований журнал не ведёт |
| Научная работа | пласта нет | Научной работы журнал не ведёт |
