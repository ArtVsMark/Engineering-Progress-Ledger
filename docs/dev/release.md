# Выпуск журнала: что значит номер

> **Читатель:** тот, кто выпускает журнал, и тот, кто читает его по выпускам.

Номер журнала устроен так же, как у механизмов поставщика: `МАЖОР.МИНОР.ПАТЧ`.
Источник номера один — файл [`CONTRACT_VERSION`](../../CONTRACT_VERSION); руками
номер нигде больше не пишется
([035](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/035-version-is-never-edited-by-hand.md)).

## Что двигает разряд

| разряд | когда растёт |
|---|---|
| мажор | журнал полностью интегрирован с механизмами поставщика — тогда выходит `1.0.0`; до этого мажор `0` |
| минор | существенная перемена в журнале — например, смена стилистики отчёта снимка |
| патч | всё остальное: свод, конвейер, документы, новый снимок прежнего вида |

Номер говорит, **чего** он версия: журнала как продукта для читателя, а не
отдельного снимка
([164](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/164-a-version-says-what-it-versions.md)).
Сам снимок не версионируется: он датирован и не правится.

## Как выпускается

Журнал изменений собирается из фрагментов `changelog.d/` при выпуске, а не
правкой общего файла
([030](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/030-changelog-from-fragments.md));
форма фрагмента — [`changelog.d/README.md`](../../changelog.d/README.md). Выпуск
идёт прогоном [`release`](../../.github/workflows/release.yml) кнопкой: он
поднимает номер, собирает `CHANGELOG.md` и ставит тег.
